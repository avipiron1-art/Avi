# Shiftly – מערכת לניהול עובדים, משמרות, נוכחות ומשימות

מערכת Web מלאה (Full-Stack) בעברית וב-RTL לניהול כוח אדם בעסק: עובדים, סידורי עבודה, שעון נוכחות, משימות, בקשות עובדים, התראות, דוחות ויומן פעולות.
המערכת עובדת מקצה לקצה – כל הנתונים נשמרים בבסיס נתונים, ההרשאות נאכפות בשרת, והממשק מותאם למחשב ולטלפון.

## הפעלה מהירה

דרישות: Node.js 20 ומעלה.

```bash
npm install
npm run build      # בניית ממשק המשתמש
npm start          # http://localhost:3000
```

בהפעלה הראשונה נוצר בסיס נתונים (`data/shiftly.db`) עם נתוני דמו.
לאיפוס הנתונים לנתוני הדמו: `npm run seed`.

פיתוח עם טעינה חמה: `npm run dev` (שרת על פורט 3000 + Vite על http://localhost:5173).
בדיקות אוטומטיות: `npm test`.

## העלאה לאינטרנט (Render) – גם מהטלפון

1. פותחים את https://render.com/deploy?repo=https://github.com/avipiron1-art/Avi ונרשמים עם חשבון GitHub.
2. מאשרים ל-Render גישה לריפו, נותנים שם לשירות ולוחצים **Deploy Blueprint**. ההגדרות נקראות אוטומטית מהקובץ `render.yaml`.
3. אחרי כמה דקות מתקבלת כתובת בסגנון `https://shiftly-xxxx.onrender.com` – נכנסים אליה עם משתמשי הדמו.

> **מגבלות התוכנית החינמית:** השרת נרדם אחרי 15 דקות ללא שימוש (הכניסה הבאה לוקחת כחצי דקה), ובסיס הנתונים **מתאפס לנתוני הדמו** בכל הפעלה מחדש או עדכון. לשימוש אמיתי עם שמירת נתונים: משדרגים את השירות לתוכנית בתשלום, מוסיפים Disk (למשל ב-`/var/data`) ומגדירים משתנה סביבה `DB_FILE=/var/data/shiftly.db`.

## הרשאות

| הרשאה | מנהל ראשי | מנהל משמרת | עובד |
|---|:-:|:-:|:-:|
| צפייה בעובדים | ✓ | ✓ | – |
| הוספה/עריכה/מחיקה של עובדים, צפייה בשכר | ✓ | – | – |
| הערות מנהל | ✓ | ✓ | – |
| צפייה בכל המשמרות | ✓ | ✓ | המשמרות שלו |
| יצירה ועריכה של משמרות | ✓ | – | – |
| עדכון נוכחות, דיווח אירועים | ✓ | ✓ | החתמת שעון עצמית |
| ניהול משימות | ✓ | ✓ | עדכון סטטוס למשימות שלו |
| אישור בקשות | ✓ | – | הגשת בקשות |
| דוחות, הגדרות, משתמשים, יומן פעולות | ✓ | – | – |

ההרשאות של "מנהל משמרת" ו"עובד" ניתנות לשינוי בהגדרות ← הרשאות. כל בדיקה מתבצעת בשרת (`requirePerm` / סינון שאילתות לפי המשתמש); הממשק רק מסתיר את מה שאין הרשאה אליו.

## אבטחה

- **סיסמאות** – bcrypt (cost 12), מדיניות סיסמה חזקה.
- **Sessions** – טוקן אקראי של 256 ביט ב-Cookie מסוג `HttpOnly` + `SameSite=Strict` (+ `Secure` ב-production); בשרת נשמר רק ה-hash של הטוקן. תפוגה, ניתוק כל המכשירים בשינוי/איפוס סיסמה, השבתת משתמש או שינוי תפקיד.
- **CSRF** – Double-submit token בכל בקשה שמשנה נתונים.
- **Rate limiting** להתחברות ולאיפוס סיסמה, ונעילת חשבון זמנית אחרי 5 ניסיונות כושלים. הודעת שגיאה זהה למשתמש שלא קיים (ללא חשיפת משתמשים).
- **SQL Injection** – כל השאילתות פרמטריות (prepared statements); עמודות מיון מתוך רשימה סגורה.
- **XSS** – React מבצע escaping, Content-Security-Policy קשיח (helmet), ולידציה לתמונות (`data:image` בלבד).
- **ולידציה בצד השרת** – zod לכל קלט, עם הודעות שגיאה בעברית לכל שדה, ו-CHECK/FOREIGN KEY בבסיס הנתונים.
- **Audit log** – נשמרים משתמש, פעולה, מועד, ערך קודם וחדש ו-IP. היומן בלתי ניתן לשינוי גם ברמת בסיס הנתונים (Triggers שחוסמים UPDATE/DELETE).
- **ייצוא** – הגנה מפני CSV/Formula injection.

## ארכיטקטורה

```
server/
  index.js            Express: helmet, cookies, auth, CSRF, routes, טיפול שגיאות מרכזי
  config.js
  db/schema.sql       סכמת בסיס הנתונים (טבלאות, FK, אינדקסים, CHECK, Triggers)
  db/seed.js          נתוני דמו
  middleware/auth.js  Sessions, הרשאות, CSRF
  lib/                זמנים, ולידציה, חישובי נוכחות, שדות משותפים
  services/           audit, notifications, permissions, settings, reports, mailer, jobs
  routes/             auth, dashboard, employees, shifts, attendance, tasks, requests,
                      notifications, reports, search, admin (users/settings/meta/audit)
  tests/              בדיקות אינטגרציה (node:test)
client/src/
  lib/                api client, auth context, toast, פורמטים ותוויות
  components/         UI kit, Layout, חיפוש גלובלי, טופס משמרת, גרפים, שעון נוכחות
  pages/              עמוד לכל מודול
```

- **Backend**: Node.js + Express, SQLite (better-sqlite3, WAL).
- **Frontend**: React 18 + React Router + Vite, Recharts, lucide-react, CSS מותאם עם Design Tokens (בהיר/כהה).
- **בסיס נתונים**: `roles`, `role_permissions`, `users`, `sessions`, `password_resets`, `employees`, `departments`, `positions`, `locations`, `employee_notes`, `shifts`, `attendance`, `incidents`, `tasks`, `requests`, `availability`, `notifications`, `audit_logs`, `settings`.
  זמני התכנון נשמרים רק במשמרת וזמני הביצוע רק בנוכחות; שעות, איחורים ושעות נוספות מחושבים ולא נשמרים כפולים.
- **משימות רקע** (`services/jobs.js`) – כל דקה: זיהוי עובדים שלא החתימו כניסה (התראה למנהלים ולעובד) ומשימות שמתקרבות ליעד.

### הרחבות עתידיות

המבנה מודולרי ומוכן להרחבה:
- **סניפים** – טבלת `locations` כבר קיימת ומקושרת לעובדים ולמשמרות.
- **מערכת שכר** – `services/reports.js` מחשב שעות רגילות/נוספות ועלות; ניתן להוסיף טבלת תעריפים ומודול תלושים.
- **החתמת מיקום (GPS)** – להוסיף עמודות מיקום ל-`attendance` ובדיקת מרחק ב-`/attendance/clock-in`.
- **אפליקציית עובדים** – כל הפונקציונליות חשופה כ-REST API תחת `/api`.
- **אינטגרציות** – `services/notify.js` ו-`services/mailer.js` הן נקודות ההרחבה לאימייל/SMS/WhatsApp/Push.

### הערות לסביבת Production

- הגדירו `NODE_ENV=production` (Cookies מאובטחים) והפעילו מאחורי HTTPS.
- `DEMO_MODE=false` – קישור איפוס הסיסמה לא יוחזר ב-API; חברו ספק דואר ב-`server/services/mailer.js`.
- `APP_URL` – כתובת המערכת לקישורי האיפוס. `DB_FILE` – מיקום קובץ בסיס הנתונים. `PORT` – פורט.
- ייצוא PDF מתבצע דרך חלון ההדפסה של הדפדפן ("שמירה כ-PDF") עם עיצוב הדפסה ייעודי, כדי לשמור על עברית ו-RTL תקינים.
